# controldctl Command Reference

This is a browsable reference for every `controldctl` command, generated by
running the real binary's `--help` output. `controldctl` is also fully
self-discoverable at runtime:

```bash
controldctl [command] --help   # human-readable help for any command
controldctl __schema           # machine-readable schema (ax or mcp format)
```

If this document and the live `--help`/`__schema` output ever disagree, the
live output wins — it is generated directly from the same Cobra command tree
that runs the CLI, while this file is a snapshot maintained by hand.

`__schema` and `completion` (Cobra's built-in shell-completion generator) are
not resource commands and are not documented here; run
`controldctl __schema --help` or `controldctl completion --help` directly.

## Global flags

Every command, including every one documented below, accepts these
persistent flags in addition to any command-specific flags listed in its own
table:

**Note on "Default" values:** Some flags are only sent to the server if you
explicitly pass them; if omitted, the field is not sent and the server keeps
the current value. Such flags are marked as "unset" in the Default column. By
contrast, flags showing a concrete value like `true`, `false`, or `0` are sent
on every request, even if you don't pass them, so omitting them resets the
field to that concrete value.

| Flag | Type | Default | Required | Description |
|------|------|---------|----------|--------------|
| `--api-token` | string | | No | ControlD API token (overrides `CONTROLD_API_TOKEN` and `--config`) |
| `--config` | string | | No | Hujson config file path with an `api_token` field |
| `--dry-run` | bool | `false` | No | emit the envelope without side effects |
| `--format` | string | | No | output format: `json` or `human` |
| `--idempotency-key` | string | | No | opaque key used to prevent duplicate-create retries |
| `--yes` | bool | `false` | No | confirm a confirmation-gated operation |

Two of these matter enough to call out for every mutating command below:

- **`--dry-run`** suppresses the underlying API call for every command that
  creates, updates, or deletes something (every `create`, `update`, and
  `delete` command, plus `profiles options update`, `profiles filters
  update`, and `profiles services update`). The command still validates
  flags and resolves credentials, and it still returns the normal JSON
  envelope, but the `data` fields reflect an operation that did not run and
  `meta.dry_run` is `true`. Read-only `list`/`types` commands ignore
  `--dry-run` because they have no side effect to suppress.
- **`--yes`** is required by the four commands gated on explicit
  confirmation: `devices delete`, `profiles delete`, `profiles rules
  delete`, and `profiles folders delete`. In machine mode (`--format=json`,
  or non-TTY output with no `--format` given) omitting `--yes` fails
  immediately with a `confirmation_required` error (exit code 2) and an
  `actionable_fix` of "pass --yes to confirm this operation". In human mode
  it instead prompts interactively with `subject? [y/N]` on stderr.

Credential precedence is `--api-token` > `CONTROLD_API_TOKEN` env var >
`--config`'s `api_token` field.

## Devices

Commands under `controldctl devices` manage ControlD devices (endpoints).

### `controldctl devices list`

List all devices.

No command-specific flags beyond the global flags above.

#### Example

```bash
controldctl devices list --format=json
```

### `controldctl devices create`

Create a device.

| Flag | Type | Default | Required | Description |
|------|------|---------|----------|--------------|
| `--ddns-ext-host` | string | | No | external DDNS hostname |
| `--ddns-ext-status` | bool | unset | No | enable (`true`) or disable (`false`) external DDNS |
| `--ddns-status` | bool | unset | No | enable (`true`) or disable (`false`) ControlD DDNS |
| `--ddns-subdomain` | string | | No | ControlD DDNS subdomain |
| `--icon` | string | `desktop-linux` | No | device icon name |
| `--legacy-ipv4-status` | bool | unset | No | enable (`true`) or disable (`false`) the legacy IPv4 resolver |
| `--name` | string | | Yes | device name |
| `--profile-id` | string | | Yes | profile PK to assign |
| `--remap-client-id` | string | | No | client ID to remap this device to |
| `--remap-device-id` | string | | No | device PK to remap this device to |

#### Example

```bash
controldctl devices create \
  --name "Laptop" \
  --profile-id abc123 \
  --icon desktop-mac \
  --format=json
```

**Dry-run:** supported. `--dry-run` returns the envelope without creating
the device; `data` fields come back zero-valued and `meta.dry_run` is `true`.

### `controldctl devices update`

Update a device.

| Flag | Type | Default | Required | Description |
|------|------|---------|----------|--------------|
| `--ddns-ext-host` | string | | No | external DDNS hostname |
| `--ddns-ext-status` | bool | unset | No | enable (`true`) or disable (`false`) external DDNS |
| `--ddns-status` | bool | unset | No | enable (`true`) or disable (`false`) ControlD DDNS |
| `--ddns-subdomain` | string | | No | ControlD DDNS subdomain |
| `--device-id` | string | | Yes | device PK to update |
| `--legacy-ipv4-status` | bool | unset | No | enable (`true`) or disable (`false`) the legacy IPv4 resolver |
| `--name` | string | | No | new device name |
| `--profile-id` | string | | No | new profile PK to assign |

#### Example

```bash
controldctl devices update \
  --device-id dev_abc123 \
  --name "Laptop (renamed)" \
  --format=json
```

**Dry-run:** supported. `--dry-run` returns the envelope without applying
the update.

### `controldctl devices delete`

Delete a device.

| Flag | Type | Default | Required | Description |
|------|------|---------|----------|--------------|
| `--device-id` | string | | Yes | device PK to delete |

#### Example

```bash
controldctl devices delete --device-id dev_abc123 --yes --format=json
```

**Confirmation required:** this command is gated by `ax.Confirm`. Pass
`--yes` to proceed in machine mode, or confirm interactively at the `[y/N]`
prompt in human mode; otherwise it fails with `confirmation_required` (exit
code 2).

**Dry-run:** supported (combine with `--yes`, since confirmation is checked
first). `--dry-run` returns `data.deleted: false` without deleting anything.

### `controldctl devices types`

List available device types and icons.

No command-specific flags beyond the global flags above.

#### Example

```bash
controldctl devices types --format=json
```

## Profile Custom Rules

Commands under `controldctl profiles rules` manage a profile's custom domain
rules, scoped to a rule folder.

### `controldctl profiles rules list`

List custom rules in a rule folder.

| Flag | Type | Default | Required | Description |
|------|------|---------|----------|--------------|
| `--folder-id` | string | | Yes | rule folder ID |
| `--profile-id` | string | | Yes | profile PK |

#### Example

```bash
controldctl profiles rules list \
  --profile-id abc123 \
  --folder-id folder_1 \
  --format=json
```

### `controldctl profiles rules create`

Create custom rules for one or more hostnames.

When `--do=3` (redirect), `--via` is required and validated locally — the command will reject the request if you omit it.

| Flag | Type | Default | Required | Description |
|------|------|---------|----------|--------------|
| `--do` | int | `0` | No | action: `0`=block, `1`=bypass, `2`=spoof, `3`=redirect |
| `--enabled` | bool | `true` | No | enable (`true`) or disable (`false`) the rule |
| `--group` | int | unset | No | rule folder PK to place the rules in (`0` = default folder) |
| `--hostnames` | string | | Yes | comma-separated hostnames |
| `--profile-id` | string | | Yes | profile PK |
| `--via` | string | | No | IPv4 redirect target (required when `--do=3`) |
| `--via-v6` | string | | No | IPv6 redirect target (used with `--do=3`) |

#### Example

```bash
controldctl profiles rules create \
  --profile-id abc123 \
  --hostnames ads.example.com,tracker.example.com \
  --do 0 \
  --format=json
```

**Dry-run:** supported. `--dry-run` returns the envelope (`data.rules` comes
back empty) without creating anything.

### `controldctl profiles rules update`

Update custom rules for one or more hostnames.

This command replaces the entire rule: `--do` and `--enabled` are always sent to the server on every request. When using `--via`, `--via-v6`, or `--group`, you must explicitly pass both `--do` and `--enabled`, or the command will error rather than silently overwriting your rule's action and status.

| Flag | Type | Default | Required | Description |
|------|------|---------|----------|--------------|
| `--do` | int | `0` | No | action: `0`=block, `1`=bypass, `2`=spoof, `3`=redirect |
| `--enabled` | bool | `true` | No | enable (`true`) or disable (`false`) the rule |
| `--group` | int | unset | No | rule folder PK to place the rules in (`0` = default folder) |
| `--hostnames` | string | | Yes | comma-separated hostnames |
| `--profile-id` | string | | Yes | profile PK |
| `--via` | string | | No | IPv4 redirect target (required when `--do=3`) |
| `--via-v6` | string | | No | IPv6 redirect target (used with `--do=3`) |

#### Example

```bash
controldctl profiles rules update \
  --profile-id abc123 \
  --hostnames ads.example.com \
  --do 1 \
  --format=json
```

**Dry-run:** supported. `--dry-run` returns the envelope without applying
the update.

### `controldctl profiles rules delete`

Delete the custom rule for a hostname.

| Flag | Type | Default | Required | Description |

## MCP Server

### `controldctl mcp-server`

Expose this CLI's command tree as a live Model Context Protocol (MCP)
server. Every non-hidden command (minus the reserved `__schema`,
`mcp-server`, and `completion` commands) becomes a tool; `tools/call` runs
the command in machine mode and returns its payload. Serves over stdio by
default, or streamable HTTP (loopback unless `--allow-non-loopback` is set).

| Flag | Type | Default | Required | Description |
|------|------|---------|----------|--------------|
| `--addr` | string | `127.0.0.1:8080` | No | HTTP bind address; loopback by default (used with `--transport=http`) |
| `--allow-non-loopback` | bool | `false` | No | allow the HTTP transport to bind a non-loopback address (fail-closed without it) |
| `--transport` | string | `stdio` | No | MCP transport: `stdio` or `http` |

#### Examples

```bash
controldctl mcp-server
controldctl mcp-server --transport=http --addr=127.0.0.1:8080
controldctl mcp-server --transport=http --addr=0.0.0.0:8080 --allow-non-loopback
```

`controldctl --mcp` is a shorthand that rewrites to `controldctl mcp-server`
before the rest of the arguments are parsed, so `controldctl --mcp
--transport=http` behaves identically to `controldctl mcp-server
--transport=http`.

Global flags passed to `mcp-server` itself (`--api-token`, `--config`,
`--dry-run`, `--yes`, `--idempotency-key`) become the defaults applied to
every tool call the server executes on behalf of an MCP client — for
example, starting the server with `--dry-run` makes every mutating tool call
through it a dry run.
